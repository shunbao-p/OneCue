# Image 2 关键帧工作流 v1

Image 2 是 Codex 制作阶段的图片能力，不嵌入包 A，不读取或保存 API 密钥。包 A 只消费已经落盘、可解码并登记 SHA-256 的图片。当前第一版把每张入选图直接作为一个静态镜头，不为图片动态化额外拆层或预留运动素材。

## 输入

开始生成前，先从 Brief 和镜头表确定：

- 题材、受众、事实与授权边界；
- 全片统一的角色、品牌、时代、材质、色彩和画风；
- 每镜主体、场景、景别、构图、叙事作用与禁止内容；
- 9:16 竖屏构图，下方约 18% 留作字幕安全区；
- 是否有用户提供且获授权的角色、商品或风格参考图。

## 生成方法

1. 需要跨镜一致性时，先生成或选定角色/主体基准与风格基准；不需要时不强行增加参考图。
2. 每个镜头独立生成一张关键帧。提示词先重申全片不变量，再描述本镜头的主体、空间关系、景别和硬约束。
3. 禁止画面文字、字母、标志、水印和与题材冲突的现代物件；字幕由包 A 后续烧录。
4. 首图只检查与本镜叙事有关的问题。若主体身份、构图安全区、关键物件或严重畸形不合格，最多做一次针对性编辑；仍不合格时改写该镜构图，不无限重复生成。
5. 原始迭代不覆盖。最终图通过解码检查并计算 SHA-256 后，方可写入 Job Bundle。

## 生成账

任务目录应保存一份轻量生成账，至少记录：

- `shot_id`；
- 使用的提示词与参考图；
- 初次生成或定向编辑；
- 入选/拒绝理由；
- 最终文件相对路径、像素尺寸与 SHA-256。

生成账属于任务证据，不是 Schema v1 的字段，也不应写入仓库源码目录。

## 图片硬门

- 每镜有独立图片，不以一张图承载整段叙事；
- 跨镜角色、商品、品牌、时代、画风和色调在需要时保持一致；
- 主体与关键物件清晰，字幕安全区可用；
- 无严重脸手畸形、错误文字、水印、越权素材或明显时代冲突；
- 文件可解码，哈希与 Job Bundle 声明一致。

进入正式静态工作流后，由包 A/FFmpeg 规格化为 1080×1920、30 FPS、H.264/yuv420p，并按该镜头人声时长保持画面静止。
