## 使用方式

### 推荐方式：只复制一次总执行提示词

总执行提示词不收录在本文中，由当前规划会话单独提供。粘贴后，新会话应自行读取本文与实施计划，读取或创建执行记录，从第一个未完成批次连续执行到批次 7；每批仍须核对退出条件并更新记录，但通过时无需停下来请求用户确认。只有硬门失败、不可逆/破坏性选择、权限缺失、真实服务无法安全恢复或需求产生实质分叉时才暂停。

### 备用方式：局部复制

- 只想确认新会话理解是否正确：复制“背景熟悉提示词”；
- 某批失败、会话中断或只需局部返工：复制相应批次提示词；
- 执行记录若已有完成证据，新会话必须从第一个未完成批次继续，不得重复真实 TTS、全尺寸渲染或覆盖有效产物；
- 批次提示词可独立执行，但完整模块设计、错误码、缓存键、命令和验收阈值仍以实施计划为准，不在每段重复全文；
- 若执行现实与计划有小幅冲突，优先选择不改变 Schema、不破坏 V1、代码更小且可验证的实现，并把差异写入执行记录；涉及产品目标、公共契约或破坏性迁移时才停下。

## 批次划分说明

| 批次 | 是否与相邻批次合并 | 原因 |
| --- | --- | --- |
| 1. 架构与红灯 | 不合并 | 先阻断回接 Web/V1 和重造 Schema，后续实现才不会整体返工 |
| 2. 运行与媒体底座 | 不合并 | 进程取消、原子文件和媒体校验是所有昂贵步骤的共同安全边界 |
| 3. TTS 与音频 | 不合并 | 涉及真实包 B、重试、缓存和较昂贵调用，应先小范围收口 |
| 4. 字幕与镜头 | 不合并 | 24 组基础运镜、ASS 和全尺寸规格需要独立实机验证 |
| 5. 时间线与状态 | 不合并 | 跨镜头数学、分层缓存和报告会决定后续重渲是否可信 |
| 6. CLI 与恢复 | 不合并 | 信号、退出码、选择性范围和故障注入需要在核心稳定后验证 |
| 7. 真实总验收 | 不合并 | 昂贵六镜头实跑只在前置硬门通过后进行，避免无谓重复 |

总执行提示词可在同一会话自动连续完成七批，但每批仍须更新执行记录并检查退出条件；连续推进不等于跳过阶段门。真实 TTS、全尺寸渲染和 QuickTime 验收应复用已有有效产物，不能为了“重新证明”而无意义重复。
