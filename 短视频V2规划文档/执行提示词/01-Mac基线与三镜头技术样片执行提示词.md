# 短视频 V2 计划 01：分批执行提示词

本文档服务于《01-Mac 基线与三镜头技术样片计划》。通常不需要逐段复制：用户先在新会话粘贴由规划会话单独提供的“总执行提示词”，新会话便应读取本文、按批次自动实施。本文中的背景提示词和五个阶段提示词主要用于只读预热、局部重跑、失败恢复或用户主动要求分批控制。

本文采用“总提示词管全局、计划文档管事实、阶段提示词管局部动作”的分工：

- 总提示词负责读取文档、全局约束、连续推进、阶段门、执行记录和最终完成条件；
- 总体规划与实施计划负责项目背景、完整技术细节、文件路径、命令、验收阈值和风险；
- 背景提示词只做只读熟悉，不实施；
- 阶段提示词只补充该批的目标、动作、验证与退出条件，并保留可独立执行所需的最小安全规则；
- 执行记录负责让新会话、续接会话和最终验收知道真实做过什么，而不依赖聊天记忆。

以下仅供选择新会话模型，不要复制进提示词正文。若界面中的模型名称不同，选择最接近的 frontier/high 或更高质量编码档位。

| 入口/批次 | 建议模型与推理强度 | 原因 |
| --- | --- | --- |
| 总执行提示词 | `gpt-5.6-sol / high` 或同等级 frontier/high | 需要跨文档理解、连续五批实施、FFmpeg 调试、测试和视觉复核，低质量执行会造成较大返工 |

## 使用方式

### 推荐方式：只复制一次总执行提示词

总执行提示词不收录在本文中，由当前规划会话单独提供。粘贴后，新会话应自行读取本文和实施计划，创建执行记录，从批次 1 连续执行至批次 5；只有计划定义的硬门失败、需要用户进行不可逆选择或缺少必要权限时才暂停。

### 备用方式：局部复制

- 想先确认新会话是否理解项目：复制“背景熟悉提示词”；
- 某一批失败或会话中断：复制对应批次提示词；
- 已有执行记录时，新会话必须从记录确认已完成批次，不得重复昂贵工作；
- 阶段提示词是独立安全入口，但完整技术参数仍以实施计划为准，不在每段重复抄写七百余行内容。

## 批次划分说明

| 批次 | 是否与相邻批次合并 | 原因 |
| --- | --- | --- |
| 1. 基线 | 不合并 | 真实 TTS/V1 若失败，继续生图和开发会掩盖基础问题 |
| 2. 素材 | 不合并 | ImageGen 与视觉一致性是独立质量门，也可能需要一次人工/Codex 选图 |
| 3. 实验代码 | 不合并 | 应先让契约与测试通过，再让真实 TTS 和媒体渲染进入代码路径 |
| 4. 真实渲染 | 不合并 | 模型和媒体执行成本较高，失败证据应与代码建设分开 |
| 5. 验收 | 不合并 | 最终质量判断应尽量基于已经冻结的产物，避免边实现边自证 |

总执行提示词可以在同一会话中自动连续完成五批，但仍须逐批写执行记录、逐批检查退出条件；“同一会话连续执行”不等于取消阶段门。

## 进入下一批的硬性条件

1. 批次 1：真实 MF TTS 与现有 V1 MP4 成功，或仅有已记录且不阻塞样片的问题；
2. 批次 2：角色表和三张关键帧存在、可解码、无严重错误；
3. 批次 3：隔离实验代码和新增测试通过，未侵入正式 V1/V2 入口；
4. 批次 4：三段 WAV、三个标准镜头和 final.mp4 均已生成；
5. 批次 5：技术硬门、观感结论、报告和执行记录齐全，才能给出是否进入计划 02 的结论。

任何批次若遇到不可恢复的硬门失败，应停止后续昂贵工作，更新执行记录并报告阻塞证据；普通低影响问题、可接受警告和非当前范围事项不得成为无限停留本阶段的理由。
