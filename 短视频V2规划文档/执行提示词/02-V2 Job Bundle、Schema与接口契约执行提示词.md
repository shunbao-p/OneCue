## 使用方式

### 推荐方式：只复制一次总执行提示词

总执行提示词不收录在本文中，由当前规划会话单独提供。粘贴后，新会话应自行读取本文与实施计划，读取或创建执行记录，从第一个未完成批次连续执行到批次 5；每批仍须核对退出条件并更新记录，但通过时无需停下来请求用户确认。只有硬门失败、不可逆/破坏性选择、权限缺失或需求产生实质分叉时才暂停。

### 备用方式：局部复制

- 只想确认新会话理解是否正确：复制“背景熟悉提示词”；
- 某批失败、会话中断或只需局部返工：复制相应批次提示词；
- 执行记录若已有完成证据，新会话必须从第一个未完成批次继续，不得重复生成 fixture、重写 Schema 或重跑无关昂贵工作；
- 批次提示词可独立执行，但完整字段、错误码、路径规则与命令仍以实施计划为准，不在每段重复全文。

## 批次划分说明

| 批次 | 是否与相邻批次合并 | 原因 |
| --- | --- | --- |
| 1. 证据与红线 | 不合并 | 若计划 01 事实或正式边界理解错误，后续 Schema 会整体返工 |
| 2. Schema 与夹具 | 不合并 | 先冻结可读结构，再实现运行校验，便于审查字段是否过度设计 |
| 3. Python 校验 | 不合并 | 路径、哈希和条件语义风险最高，应独立测试和收口 |
| 4. CLI 与迁移 | 不合并 | 需要证明接口和真实三镜头事实可用，而不只是单元函数自洽 |
| 5. 审计与交接 | 不合并 | 最终契约冻结应基于完整证据，并与旧基线失败清楚区分 |

总执行提示词可在同一会话自动连续完成五批，但每批仍须更新执行记录并检查退出条件；连续推进不等于跳过阶段门。

## 进入下一批的硬性条件

1. 批次 1：计划 01 PASS 与字段采用/迁移/废弃表已记录，测试按预期红灯，未触碰 V1/包 B；

3. 批次 3：正式 Python 校验器只读、纯标准库，正向与负向矩阵通过；
4. 批次 4：CLI 0/2/1、稳定 JSON、输入不变与计划 01 迁移验证通过；
5. 批次 5：契约一致性审计完成，新增测试通过，包 A 无本计划新增回归，执行记录和计划 03 交接齐全。

任何批次若遇到不可恢复的硬门失败，应停止后续工作、更新执行记录并报告证据；普通低影响问题、已知旧失败、图片动态观感和非当前范围事项不得成为无限停留本阶段的理由。
