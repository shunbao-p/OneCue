### 7.7 客观能力边界与最终工具分类

- FFmpeg 的微放大、推拉、平移是虚拟摄影机运动；不能产生雨落、人物摆动、旗帜、烟雾等画面对象自身运动。用户偏好的微放大保留为正式默认，缺少叙事依据的左右晃动不推荐。
- DepthFlow 只能由估深形成视差/换视点，本质仍是摄影机运动，不能满足语义动态；它对建筑组虽相对胜出，但没有越过用户的“真正动态”质量门。
- HyperFrames 可以真实生成随时间变化的程序化雨线、雾、灯光与 DOM 信息动画；也能在人工切层后做 2D puppet。但当前自然场景雨层过弱、人物只做整体推进，用户未感知到有效场景内/主体内运动。进一步人物摆动需透明分层、枢轴与遮挡处理，人工重且易有纸片感。
- 衣发、表情、肢体、雨水与环境自然联动属于 I2V/视频扩散或专门角色动画范畴；当前 FFmpeg、DepthFlow 与 HyperFrames 构图均不能自动完成。本地 I2V 理论上可在 M1 Pro 32GB 试小型量化模型，但用户未授权，且约 9.344 GiB 模型、推理时长、身份漂移与许可风险仍未实测。

| 最终分类 | 工具/路线 | 结论 |
| --- | --- | --- |
| `formal_candidate` | **无** | 用户主观质量门明确未过，不以相对选择凑候选 |
| `manual_only` | HyperFrames designed-info | 信息图、路线、警灯、档案状态等少量设计镜头；用户认为动态更明显 |
| `research_only` | MFLUX | 冷下载耗时失控；模型未完整取得 |
| `research_only` | Draw Things / 本地 I2V | 用户未授权，未下载/安装；它才是自然语义运动的正确候选类别之一 |
| `rejected` | DepthFlow 正式/人工路线 | 视差不能满足真正动态预期，收益不足以承担 AGPL/取消原子性成本 |
| `rejected` | HyperFrames layered-environment / narrative-character | 当前实现的自然场景增益不足；不把弱雨层、整体推进或晃动包装成高级动态 |
